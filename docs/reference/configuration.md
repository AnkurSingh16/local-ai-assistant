# Configuration reference

All configuration comes from environment variables, validated with Zod in `apps/api/src/config.ts` when the API starts. If a value is invalid, the API refuses to start and names the variable, without printing its value. Node loads a `.env` file at the repository root if one exists (`--env-file-if-exists`); `.env.example` lists every variable.

| Variable                | Default                                       | Meaning                                                                                                                                                                        |
| ----------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `NODE_ENV`              | `development`                                 | `development`, `test` or `production`. Production refuses `PROVIDERS=mock`.                                                                                                    |
| `HOST`                  | `127.0.0.1`                                   | Bind address. Anything other than loopback logs a `server_exposed` warning.                                                                                                    |
| `PORT`                  | `8787`                                        | API port.                                                                                                                                                                      |
| `LOG_LEVEL`             | `info`                                        | pino level. Logs never contain message text.                                                                                                                                   |
| `PROVIDERS`             | `ollama`                                      | `mock` runs the deterministic chat and moderation providers, for end-to-end tests and demos without Ollama.                                                                    |
| `OLLAMA_BASE_URL`       | `http://127.0.0.1:11434`                      | Ollama's address.                                                                                                                                                              |
| `CHAT_MODEL`            | `qwen2.5:7b`                                  | Chat model. `llama3.1:8b` is the allowed alternative; `llama3.2:3b` below 16 GB of RAM.                                                                                        |
| `GUARD_MODEL`           | `llama-guard3:1b`                             | Safety classifier: `llama-guard3:1b` below 24 GB of RAM, `llama-guard3:8b` above ([ADR-0006](../adr/0006-guard-model-size.md)).                                                |
| `OLLAMA_KEEP_ALIVE`     | `30m`                                         | How long Ollama keeps a model loaded after a call, such as `30m` or `1h`.                                                                                                      |
| `GUARD_TIMEOUT_MS`      | `20000`                                       | Upper bound on a guard check that may need a model load. A timeout refuses with `unavailable`.                                                                                 |
| `GUARD_WARM_TIMEOUT_MS` | `2000`                                        | Upper bound on a guard check when Ollama's `/api/ps` shows the guard model already loaded. Reading `/api/ps` adds up to 0.5 s; if it fails, the check gets `GUARD_TIMEOUT_MS`. |
| `SEARXNG_URL`           | `http://127.0.0.1:8888`                       | SearXNG's loopback address from `compose.yaml`.                                                                                                                                |
| `SEARCH_TIMEOUT_MS`     | `5000`                                        | Upper bound on one `web_search` (ADR-0003). A timeout is reported to the model as an unavailable search.                                                                       |
| `TURN_TIMEOUT_MS`       | `60000`                                       | Upper bound on a whole turn.                                                                                                                                                   |
| `ALLOWED_HOSTS`         | `localhost:<PORT>,127.0.0.1:<PORT>`           | Accepted `Host` headers, comma-separated. Anything else gets 403, which stops DNS rebinding.                                                                                   |
| `ALLOWED_ORIGINS`       | `http://localhost:5173,http://127.0.0.1:5173` | Browser origins allowed to call the API. Requests with any other `Origin` get 403.                                                                                             |
| `RATE_LIMIT_PER_IP`     | `60`                                          | Chat turns per IP (IPv6 grouped by /64) per window.                                                                                                                            |
| `RATE_LIMIT_WINDOW_MS`  | `600000`                                      | Rate-limit window, 10 minutes.                                                                                                                                                 |
| `MAX_CONCURRENT_TURNS`  | `2`                                           | Turns running at once. Ollama generates one at a time with `OLLAMA_NUM_PARALLEL=1`.                                                                                            |
| `MAX_QUEUED_TURNS`      | `4`                                           | Turns waiting for a slot. Beyond that the API answers 503 with `Retry-After`.                                                                                                  |

Fixed limits that are not configurable: a 16 KB request body, 4,000 characters per message, `num_ctx` 8,192 for chat and 2,048 for the guard.

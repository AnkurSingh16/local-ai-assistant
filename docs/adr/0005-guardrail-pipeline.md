# ADR-0005: Guardrail pipeline, fail-closed moderation and refusals

- **Status:** Accepted
- **Date:** 2026-11-12
- **Deciders:** Ankur Pawar

## Context

Safety is the top priority. Tay learned from abusive users, early Bing Chat drifted into hostility in long sessions, and Grok published offensive output after an unreviewed change. No single layer is trusted. The classifier, `llama-guard3`, does not claim to detect prompt injection or plain insults, so other layers must cover those.

## Options considered

1. **`llama-guard3` only.** Simple, but misses injection, insults aimed at the user and encoded payloads.
2. **Layered rules plus `llama-guard3`, failing open** when the classifier is unavailable. Available, but a crashed classifier sends raw input to the model and unmoderated output to the user.
3. **Layered rules plus `llama-guard3`, failing closed.**

## Decision

Option 3, in this order, cheapest and most deterministic first:

1. Rate limits per session and per IP, and a global cap of two concurrent turns ([ADR-0011](0011-search-cache-and-rate-limits.md)).
2. Size limits: Fastify `bodyLimit` 16 KB and a Zod maximum of 4,000 characters per message.
3. Normalisation: NFKC; strip zero-width characters, bidi controls and Unicode tag characters (U+E0000 to U+E007F); neutralise template tokens; decode embedded base64, hex and rot13 runs for inspection only.
4. Rules baseline over the normalised and decoded text: slurs, sexual content involving minors, abuse aimed at the assistant or others, and injection or jailbreak phrases (role-play overrides, "ignore previous instructions", system-prompt extraction).
5. `llama-guard3` input check (user role).
6. Persona and prompt assembly ([ADR-0004](0004-context-budget-and-history.md)).
7. The agent loop ([ADR-0003](0003-agent-loop-and-tools.md)).
8. Output moderation with a hold-back buffer. Text is released one paragraph at a time: at a blank line, or at a sentence boundary after 500 characters. A fenced code block is held as one unit up to 2,000 characters; a longer block is split at line boundaries into chunks of at most 2,000 characters, each moderated before release. Each paragraph passes output rules (insults, claims of feelings or of being human, first-person political opinions, a canary string from the system prompt, high overlap with the system prompt) and `llama-guard3` in the assistant role before it is released. Generation continues while the previous paragraph is checked. A citation event is sent only after the paragraph that cites it is released.
9. Only text that passed is stored.

**On a flag:** input is answered with a fixed, calm refusal and never reaches the chat model or storage. Output stops generation and sends a fixed refusal; paragraphs already released stay, because they passed. Refusals are fixed templates, never generated by the model, and name no rule or category: the client sees one of `policy`, `self_harm`, `unavailable` or `rate_limited`.

**Self-harm** returns a supportive message with crisis resources (988 in the US, findahelpline.com, and the local emergency number, configurable by locale) instead of a refusal, without calling the chat model.

**Contested topics** are handled in the persona: balanced, factual overviews and no personal political opinion; the output rules catch first-person opinions.

**Failing closed.** The guard model is loaded at API startup, and the API reports not ready until a warm-up classification succeeds. A check that needs a model load gets 20 s, because I measured a 15.5 s guard load while the chat model was generating ([ADR-0006](0006-guard-model-size.md)); a check with the guard already resident gets 2 s. Ollama's `/api/ps` tells the two cases apart. Guard calls use `num_ctx` 2,048. A circuit breaker opens after 5 consecutive check failures, refuses with `unavailable` for 10 s, then lets one probe through. There is no fail-open setting; development and CI use the mock moderator instead.

**Feedback, corrections and preference candidates** pass steps 3 to 5 before they are stored; flagged items are dropped.

## Consequences

- Text appears paragraph by paragraph rather than token by token, and time to first text is the first paragraph plus one guard call (26 ms warm on 1b).
- If Ollama's guard model is down, the assistant refuses rather than answering unmoderated.
- Residency is read just before each check, not held. If another load evicts the guard in between (which happens on 16 GB, [ADR-0006](0006-guard-model-size.md)), that check gets the 2 s timeout for a reload and is refused with `unavailable`. This fails closed; it costs an occasional spurious refusal.
- The rules baseline is the only layer for injection and insults, so it carries a large share of the red-team set and is tested against evasion (casing, spacing, leetspeak, confusables, encodings).

## Evidence

- On 2026-11-12, both `llama-guard3:8b` and `llama-guard3:1b` rated an insult and "ignore previous instructions" as safe in my spike, confirming the rules layer is necessary.
- Llama Guard 3 model card (hazard categories S1 to S14; no injection detection claimed): https://huggingface.co/meta-llama/Llama-Guard-3-8B (accessed 2026-11-12).
- Microsoft on Tay: https://blogs.microsoft.com/blog/2016/03/25/learning-tays-introduction/ (accessed 2026-11-12).
- On 2026-11-12 I polled `/api/ps` every 0.3 s while `llama-guard3:1b` loaded from cold: it was not listed for the first 1.5 s and was listed from 1.8 s, so a model still loading is not reported as resident.
- OWASP LLM07 System Prompt Leakage, which advises keeping nothing secret in the system prompt: https://genai.owasp.org/llmrisk/llm072025-system-prompt-leakage/ (accessed 2026-11-12).
